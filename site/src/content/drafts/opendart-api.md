[DART 공시 보는 법](/learn/dart-disclosure/) 편에서 전자공시시스템 화면에서 공시를 찾는 방법을 정리했습니다. 이번 편은 같은 공시를 프로그램으로 받는 방법입니다. **API**(Application Programming Interface)는 프로그램끼리 데이터를 주고받는 규격이고, **OpenDART**(opendart.fss.or.kr)는 금융감독원이 DART 공시를 API로 제공하는 사이트입니다. **DART**(Data Analysis, Retrieval and Transfer System)는 금융감독원 전자공시시스템입니다.

OpenDART를 처음 쓸 때 알아 둘 사실은 네 가지입니다(2026년 11월 28일 기준).

- 개인으로 신청하면 **인증키가 즉시 발급**되고, <mark>하루 **20,000건**까지 호출할 수 있습니다.</mark>
- 제공 API는 6개 분류 **85종**입니다. 공시 목록, 기업 기본정보, 정기보고서 항목, 재무제표, 지분공시, 주요사항보고서, 증권신고서를 다룹니다.
- 회사를 지정할 때는 종목코드(6자리)가 아니라 **고유번호**(8자리)를 씁니다.
- 인증키가 틀려도 응답은 HTTP 200으로 옵니다. <mark>성공 여부는 응답 본문의 **status 값으로** 확인해야 합니다.</mark>

[금융투자협회 API 신청 방법](/learn/kofia-freesis-api/) 편에서 다룬 공공데이터포털 API, [과거 주가 데이터 받는 법](/learn/krx-historical-price-data/) 편의 한국거래소 Open API와 비교하면 신청 절차가 가장 간단하지만, 호출 규칙은 OpenDART만의 것이 많습니다.

## 인증키 신청 — 개인은 즉시, 기업은 1~2영업일

OpenDART 상단 메뉴의 `인증키 신청/관리 > 인증키 신청`에서 신청합니다. 별도의 회원가입 화면이 없고, 인증키 신청이 곧 회원가입입니다.

1. **이용약관과 개인정보 수집·이용에 동의**합니다.
2. **사용자 구분**에서 개인 또는 기업을 고르고, 이메일과 비밀번호를 입력합니다.
3. **API 사용환경**(웹·앱·모두)과 **API 사용용도**를 적습니다. 확인 URL은 선택 항목입니다.
4. `등록`을 누르면 신청이 끝나고, 결과는 이메일로 옵니다. 발급된 키는 `인증키 신청/관리 > 오픈API 이용현황`에서 확인합니다.

| 구분 | 필요 서류 | 발급 시점 | 하루 이용 한도 |
| :-- | :-- | :-- | :-- |
| **개인** | 없음 | 신청 완료 후 즉시 | 전체 API 합산 20,000건 |
| **기업** (개인사업자 포함) | 1년 내 발급된 사업자등록증 또는 사업자등록증명원, 요청 IP | 담당자 승인 후(1~2영업일) | 공시검색·기업개황은 한도 없음, 나머지 API 합산 20,000건 |

<mark>한도 20,000건은 **API별 한도가 아니라 전체 합산**입니다.</mark> 예를 들어 재무제표 API를 15,000번 부르면 같은 날 공시검색은 5,000번만 남습니다. 한도를 넘으면 status `020`이 돌아옵니다.

키 관리에서 확인해 둘 규칙은 세 가지입니다.

- **한 사람이 키를 두 개 이상 받을 수 없습니다**(이용약관 제19조). 인증키를 제3자가 쓰게 해서도 안 됩니다.
- **재발급 메뉴가 없습니다.** 금융감독원 FAQ(2026년 8월 25일 등록)는 `마이페이지 > 탈퇴하기`로 탈퇴한 뒤 다시 가입하면 새 키를 받을 수 있고, 이때 기존 키는 영구 삭제된다고 안내합니다. 키가 외부에 노출됐을 때 쓰는 방법이기도 합니다.
- **개인정보 보유기간이 2년이고, 2년마다 재동의해야 합니다.** 재동의하지 않으면 회원 정보가 삭제되고 자동 탈퇴 처리됩니다. 이렇게 만료된 키로 호출하면 status `901`이 돌아옵니다. 매일 자동으로 데이터를 받는 프로그램이 어느 날 갑자기 멈췄다면 이 코드부터 확인합니다.

## 호출 속도 제한과 상업적 이용

하루 한도 외에 **분당 호출 횟수에도 제한**이 있습니다. FAQ는 <mark>분당 1,000회 이상 데이터를 가져가면 해당 IP 주소의 OpenDART 접속을 **1시간 동안 차단**한다</mark>고 안내합니다. 반복문으로 여러 회사를 차례로 조회할 때는 호출 사이에 대기 시간을 두는 것이 안전합니다.

상업적 이용에 대해서는 FAQ가 「공공데이터의 제공 및 이용 활성화에 관한 법률」에 따른 공공데이터에 해당하므로 공익이나 타인의 권리를 침해하지 않는 범위에서 공개·활용이 제한되지 않는다고 답합니다. 다만 금융감독원은 이를 이용한 서비스를 별도로 심사·승인하지 않으며, **재배포·재가공에 따른 책임은 이용자가 부담**합니다. 거래소 Open API 이용약관이 비상업 목적과 제3자 제공 금지를 정하고 있는 것과 다른 점입니다.

## 제공 API 85종의 구성

개발가이드는 API를 6개 분류로 나눕니다. 2026년 11월 28일 개발가이드 목록을 직접 집계하면 다음과 같습니다.

| 분류 | 개수 | 주요 API |
| :-- | --: | :-- |
| **공시정보** | 4 | 공시검색, 기업개황, 공시서류원본파일, 고유번호 |
| **정기보고서 주요정보** | 30 | 배당에 관한 사항, 최대주주 현황, 자기주식 취득 및 처분 현황, 임원·직원 현황, 타법인 출자현황 등 |
| **정기보고서 재무정보** | 7 | 단일회사 주요계정, 단일회사 전체 재무제표, 단일회사 주요 재무지표, 다중회사 비교 등 |
| **지분공시 종합정보** | 2 | 대량보유 상황보고, 임원·주요주주 소유보고 |
| **주요사항보고서 주요정보** | 36 | 유상증자 결정, 자기주식 취득 결정, 전환사채권 발행결정, 회사합병 결정 등 |
| **증권신고서 주요정보** | 6 | 지분증권, 채무증권, 증권예탁증권, 합병, 주식의포괄적교환·이전, 분할 |
| 합계 | 85 | |

FAQ의 이용한도 안내(2020년 1월 등록)는 한도 기준을 「오픈API 83종 전체」로 적고 있어 현재 목록과 개수가 다릅니다. 이후 API가 추가됐기 때문으로 보입니다. 예를 들어 정기보고서 주요정보에는 2026년 5월 이후 제출된 보고서에 쓰는 「이사·감사의 개인별 보수현황(5억원 이상) (Ver 2.0)」 등 Ver 2.0 API 2종이 종전 API와 함께 올라 있습니다. <mark>같은 항목이라도 보고서 제출 시점에 따라 **호출할 API가 다를 수 있으므로**</mark>, 보수 관련 데이터를 받을 때는 개발가이드의 적용 기간 안내를 먼저 확인합니다.

## 먼저 받아 둘 것 — 고유번호 파일

OpenDART의 거의 모든 API는 회사를 **고유번호**(`corp_code`, 8자리)로 지정합니다. 상장회사의 종목코드(`stock_code`, 6자리)와 다른 번호입니다. 삼성전자는 종목코드가 `005930`, 고유번호가 `00126380`입니다. 고유번호는 비상장 회사에도 부여되므로 종목코드로는 지정할 수 없는 회사까지 조회할 수 있습니다.

고유번호 목록은 **고유번호 API**(`corpCode.xml`)로 받습니다. 이 API는 다른 API와 달리 JSON이나 XML 응답이 아니라 **ZIP 파일**을 돌려줍니다. 압축을 풀면 나오는 XML 파일에 회사마다 고유번호, 정식명칭, 영문 정식명칭, 종목코드, 최종변경일자가 수록돼 있습니다. **JSON**(JavaScript Object Notation)과 **XML**(eXtensible Markup Language)은 둘 다 데이터를 구조화해 주고받는 텍스트 형식입니다.

이 파일은 실행할 때마다 받을 필요가 없습니다. FAQ는 고유번호 변경사항이 **다음 영업일 오전**에 반영된다고 안내하므로, 하루 한 번 받아 저장해 두고 종목코드와 고유번호를 대조하는 데 쓰면 됩니다.

## 공시검색 API — 조건과 기본값

**공시검색**(`list.json`)은 회사·기간·공시유형으로 공시 목록을 조회합니다. 주요 요청 인자는 다음과 같습니다.

| 요청 인자 | 내용 | 기본값·제한 |
| :-- | :-- | :-- |
| `corp_code` | 고유번호 | 없으면 전체 회사 |
| `bgn_de`, `end_de` | 검색 시작·종료 접수일자(YYYYMMDD) | 종료일 없으면 당일, 시작일 없으면 종료일과 같음 |
| `pblntf_ty` | 공시유형(A 정기공시, B 주요사항보고, C 발행공시, D 지분공시, E 기타공시, F 외부감사관련, G 펀드공시, H 자산유동화, I 거래소공시, J 공정위공시) | 없으면 전체 |
| `pblntf_detail_ty` | 공시상세유형(예: A001 사업보고서, A002 반기보고서, A003 분기보고서) | 없으면 전체 |
| `corp_cls` | 법인구분(Y 유가증권, K 코스닥, N 코넥스, E 기타) | 하나만 지정 가능 |
| `last_reprt_at` | 최종보고서만 검색할지 여부 | **N**(정정 전 보고서 포함) |
| `page_no`, `page_count` | 페이지 번호, 페이지당 건수 | 1, **10**(최대 100) |

결과가 예상보다 적거나 많을 때 원인이 되는 조건은 세 가지입니다.

**① 고유번호를 지정하지 않으면 검색기간이 3개월로 제한됩니다.** 시장 전체의 공시를 1년 치 받으려면 기간을 3개월 이하로 나눠 여러 번 호출해야 합니다.

**② 한 번에 최대 100건입니다.** `page_count`를 지정하지 않으면 10건만 옵니다. 응답의 `total_count`(총 건수)와 `total_page`(총 페이지 수)를 확인해 `page_no`를 올려 가며 나머지를 받습니다.

**③ 정정 전 보고서도 함께 나옵니다.** `last_reprt_at`의 기본값이 N이라 같은 보고서가 정정 전후로 여러 번 조회될 수 있습니다. 정정이 반영된 최종본만 필요하면 Y를 지정합니다. 보고서명(`report_nm`) 앞의 [기재정정]·[첨부정정] 같은 표시로도 정정 여부를 알 수 있습니다.

응답의 **접수번호**(`rcept_no`, 14자리)는 공시 문서를 가리키는 번호입니다. `https://dart.fss.or.kr/dsaf001/main.do?rcpNo=접수번호`로 공시 원문 화면을 열 수 있고, 공시서류원본파일 API(`document.xml`)에 넣으면 원본 파일을 ZIP으로 받을 수 있습니다. 비고(`rm`) 항목의 「정」은 제출 후 정정신고가 있었다는 뜻이고, 「철」은 철회(간주)된 보고서라는 뜻입니다.

## 기업개황 API

**기업개황**(`company.json`)은 고유번호 하나를 넣으면 회사의 기본정보를 돌려줍니다. 응답 항목은 정식명칭·영문명칭, 종목명, 종목코드, 대표자명, 법인구분, 법인등록번호, 사업자등록번호, 주소, 홈페이지·IR 홈페이지, 전화·팩스번호, 업종코드, 설립일, **결산월**입니다. 결산월(`acc_mt`)은 재무제표 API를 부르기 전에 확인할 값입니다. 12월 결산이 아닌 회사는 사업연도와 보고서 시점이 달력과 어긋나기 때문입니다.

## 재무제표 API — 3개월 금액과 누적 금액

재무 데이터는 **XBRL**(eXtensible Business Reporting Language, 재무 정보를 기계가 읽을 수 있게 만든 표준 형식)로 제출된 정기보고서에서 추출됩니다. 자주 쓰는 API는 세 가지입니다.

| API | 주소 | 제공 내용 | 제공 기간 |
| :-- | :-- | :-- | :-- |
| 단일회사 주요계정 | `fnlttSinglAcnt.json` | 재무상태표·손익계산서의 주요 계정 | 2015년 이후 |
| 단일회사 전체 재무제표 | `fnlttSinglAcntAll.json` | 재무상태표·손익계산서·포괄손익계산서·현금흐름표·자본변동표의 모든 계정 | 2015년 이후 |
| 단일회사 주요 재무지표 | `fnlttSinglIndx.json` | 수익성·안정성·성장성·활동성 지표 | **2023년 3분기 이후** |

공통 요청 인자는 고유번호, 사업연도(`bsns_year`), **보고서 코드**(`reprt_code`)입니다. 보고서 코드는 1분기보고서 `11013`, 반기보고서 `11012`, 3분기보고서 `11014`, 사업보고서 `11011`로, 숫자 순서와 분기 순서가 일치하지 않습니다. 전체 재무제표 API는 여기에 **개별/연결 구분**(`fs_div`)이 필수로 추가되며, `CFS`가 연결재무제표, `OFS`가 재무제표(별도)입니다. 연결과 별도의 차이는 [재무제표 보는 법](/learn/financial-statements-basics/) 편에서 다뤘습니다.

<mark>분기·반기보고서의 손익계산서에서는 **어느 금액 항목을 읽느냐에 따라 값이 크게 달라집니다.**</mark> 전체 재무제표 API 명세는 분·반기보고서의 (포괄)손익계산서에서 당기금액(`thstrm_amount`)을 **3개월 금액**으로, 당기누적금액(`thstrm_add_amount`)을 **연초부터의 누적 금액**으로 정의합니다. 삼성전자 2026년 3분기보고서의 연결 손익계산서 값으로 차이를 보면 다음과 같습니다.

| 삼성전자 연결 손익계산서 (2026년 3분기보고서) | 3개월 (7~9월) | 누적 (1~9월) |
| :-- | --: | --: |
| 매출액 | 195조 2,532억원 | 500조 6,261억원 |
| 영업이익 | 107조 4,405억원 | 254조 1,657억원 |

「3분기 매출액」을 계산하면서 누적 금액을 읽으면 실제보다 2.6배 큰 값이 나옵니다. 뉴스에서 말하는 분기 실적은 3개월 금액입니다.

**4분기만의 실적을 담은 보고서는 없습니다.** 사업보고서는 1년 전체의 금액을 담으므로, 4분기(10~12월) 실적은 사업보고서의 연간 금액에서 3분기보고서의 누적 금액을 빼서 계산합니다. 재무상태표는 기간이 아니라 특정 시점의 잔액이라 이런 구분이 없습니다.

그 밖에 확인해 둘 점은 세 가지입니다.

- **조회되지 않는 회사가 있습니다.** XBRL 재무제표 제출 의무가 없는 회사(일반기업회계기준을 적용하는 비상장법인 등)는 재무 API로 조회되지 않습니다. 금융업종 상장법인은 2023년 3분기보고서부터 XBRL 제출 대상이 됐습니다.
- **계정ID가 「-표준계정코드 미사용-」으로 나오는 계정이 있습니다.** 회사가 표준계정과목 대신 직접 만든 계정을 쓴 경우입니다. 여러 회사의 같은 계정을 비교할 때는 계정ID(`account_id`)를 기준으로 맞추되, 이런 계정은 계정명을 따로 확인해야 합니다.
- **금융감독원은 정확성을 보장하지 않습니다.** 개발가이드는 회사가 제출한 공시서류에서 일부 정보를 추출한 것이라고 밝히고 있고, 제출인이 재무제표를 정정하면 수치가 바뀔 수 있습니다. 중요한 숫자는 공시 원문과 대조합니다.

## 오류 코드 — HTTP 상태가 아니라 status로 판별한다

이 글을 쓰며 2026년 11월 28일 인증키 없이 직접 호출해 확인한 결과는 다음과 같습니다.

| 호출 방법 | HTTP 상태 | 응답 |
| :-- | :-- | :-- |
| 임의의 40자리 문자열을 키로 넣음 | 200 | `{"status":"010","message":"등록되지 않은 인증키입니다."}` |
| `crtfc_key=`처럼 값을 비워 둠 | 200 | `{"status":"100","message":"인증키가 누락되었습니다."}` |
| `crtfc_key` 인자를 아예 생략 | 302 | 오류 안내 페이지(`error1.html`)로 이동 |
| User-Agent를 빈 값으로 보냄 | 302 | 오류 안내 페이지(`error1.html`)로 이동 |

<mark>공공데이터포털 API는 인증 오류를 HTTP 401·403으로 돌려주지만, **OpenDART는 HTTP 200에 오류 코드를 포함해** 보냅니다.</mark> HTTP 상태만 확인하는 코드는 인증 실패를 정상 응답으로 처리하게 됩니다. 고유번호 API도 마찬가지로, 오류가 나면 ZIP 파일 대신 오류 코드를 포함한 XML이 HTTP 200으로 옵니다.

**User-Agent**는 요청을 보내는 프로그램을 알리는 머리글(헤더)입니다. FAQ는 서버에서 호출할 때 이 값이 비어 있으면 오류 페이지가 나타날 수 있으니 직접 지정하라고 안내합니다. 파이썬 표준 라이브러리(`urllib`)는 기본값을 채워 보내므로 별도 지정 없이 정상 응답을 받았습니다. 이 밖에 FAQ는 보안 강화를 위해 **TLS 1.2 이상**의 보안 연결만 지원하도록 변경했다고 안내합니다(2023년 11월 등록). **TLS**(Transport Layer Security)는 인터넷 통신을 암호화하는 규약입니다.

개발가이드의 주요 오류 코드는 다음과 같습니다.

| status | 뜻 |
| :-- | :-- |
| `000` | 정상 |
| `010` / `011` | 등록되지 않은 키 / 일시적으로 사용 중지된 키 |
| `012` | 접근할 수 없는 IP |
| `013` | 조회된 데이터가 없음 |
| `020` | 요청 제한 초과(일반적으로 20,000건 이상) |
| `021` | 조회 가능한 회사 개수 초과(최대 100건) |
| `100` | 필드의 부적절한 값(필드 설명에 없는 값을 사용) |
| `800` | 시스템 점검으로 서비스 중지 |
| `901` | 개인정보 보유기간 만료로 사용할 수 없는 키 |

`013`은 조건에 맞는 데이터가 없다는 뜻입니다. 여러 회사를 반복 조회하는 프로그램이라면 `013`을 오류로 보고 중단하지 말고, 해당 회사를 기록해 둔 뒤 다음 회사로 넘어가게 만듭니다.

## 파이썬 호출 예시

표준 라이브러리만으로 고유번호 파일을 받고 공시 목록을 조회하는 예시입니다.

```python
import io, json, urllib.parse, urllib.request, zipfile
import xml.etree.ElementTree as ET

KEY = "발급받은_40자리_인증키"
BASE = "https://opendart.fss.or.kr/api/"

def get(path, **params):
    url = BASE + path + "?" + urllib.parse.urlencode({"crtfc_key": KEY, **params})
    with urllib.request.urlopen(url, timeout=30) as r:
        return r.read()

# ① 고유번호 파일: 정상이면 ZIP, 오류면 XML이 온다
raw = get("corpCode.xml")
if raw[:2] != b"PK":                     # ZIP 파일은 PK로 시작한다
    print("오류:", raw.decode("utf-8"))
else:
    z = zipfile.ZipFile(io.BytesIO(raw))
    root = ET.fromstring(z.read(z.namelist()[0]))
    codes = {}
    for e in root.iter("list"):
        stock = (e.findtext("stock_code") or "").strip()
        if stock:                         # 비상장 회사는 종목코드가 비어 있다
            codes[stock] = e.findtext("corp_code")
    print(codes.get("005930"))           # 삼성전자 → 00126380

# ② 공시검색: HTTP 200이어도 status를 확인해야 한다
data = json.loads(get("list.json", corp_code="00126380",
                      bgn_de="20260101", end_de="20261127",
                      pblntf_ty="A", page_count=100))
if data["status"] != "000":
    print(data["status"], data["message"])
else:
    for row in data["list"]:
        print(row["rcept_dt"], row["report_nm"], row["rcept_no"])
```

②는 삼성전자가 2026년에 제출한 정기공시(사업·반기·분기보고서) 목록을 조회합니다. 고유번호를 지정했으므로 3개월 기간 제한이 적용되지 않습니다. 재무제표를 받으려면 같은 함수로 `get("fnlttSinglAcntAll.json", corp_code="00126380", bsns_year="2026", reprt_code="11014", fs_div="CFS")`처럼 호출하고, 금액 문자열의 쉼표를 제거한 뒤 숫자로 바꿔 씁니다.

## 배당 공시는 구조화된 API가 없다

[배당 캘린더 만드는 법](/learn/dividend-calendar/) 편에서 확인한 내용을 2026년 11월 28일 개발가이드로 다시 확인했습니다. **배당결정 공시의 기준일·금액·지급일을 항목별 데이터로 주는 API는 여전히 없습니다.**

- 주요사항보고서 API 36종에 배당 관련 항목이 없습니다.
- 정기보고서의 「배당에 관한 사항」 API(`alotMatter.json`)는 항목별 당기·전기·전전기 값과 결산기준일을 주지만, **배당기준일·지급일 필드는 없습니다.**
- 공시검색 API에는 보고서명으로 거르는 조건이 없습니다.

따라서 배당 일정을 자동으로 모으려면 공시검색으로 목록을 받아 보고서명(`report_nm`)에 「배당」이 들어간 공시를 직접 골라내고, 접수번호로 원문을 받아 표를 해석해야 합니다. 회사가 정기보고서에 적은 연간 배당 규모를 비교하는 데는 `alotMatter`로 충분합니다.

## 정리

- **OpenDART**는 금융감독원이 DART 공시를 API로 제공하는 사이트입니다. 개인은 **신청 즉시 인증키가 발급**되고, 기업은 서류 검토 후 1~2영업일이 걸립니다.
- 하루 한도는 **전체 API 합산 20,000건**이고, <mark>분당 1,000회 이상 호출하면 IP가 1시간 차단됩니다.</mark> 키는 1인 1개이며 2년마다 재동의하지 않으면 사용할 수 없게 됩니다.
- 제공 API는 6개 분류 **85종**입니다. 회사는 종목코드가 아니라 **고유번호**(8자리)로 지정하므로, 고유번호 파일(ZIP)을 먼저 받아 둡니다.
- 공시검색은 **고유번호 없이 3개월**, **한 번에 최대 100건**, **기본값으로 정정 전 보고서 포함**이라는 조건이 있습니다.
- 분·반기보고서 손익계산서는 **3개월 금액과 누적 금액이 따로** 있습니다. 4분기 실적은 연간 금액에서 3분기 누적 금액을 빼서 계산합니다.
- 오류는 HTTP 200에 담겨 오므로 **status 값**(정상 `000`)으로 판별합니다.
- 배당결정 공시의 기준일·지급일을 주는 구조화 API는 없습니다.
